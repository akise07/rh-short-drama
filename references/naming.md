> 建目录、命名文件、组织提示词.md 时参照。

## 目录结构

```text
<项目根>/
├── _共享资源/                    ← 全剧共享，🔴 **只有这三个目录**
│   ├── 01_角色设定/              角色设定总表.md / gen_char*.py / CH##_四视图_<风格标记>.png
│   ├── 02_场景设定/              gen_scene.py / SC##_<场景名>.png
│   └── 03_风格与提示词规范/       风格选定.md / 平台选定.md / 提示词格式 / 节奏 / 命名 / 台词口径
├── EP##/                         ← 一集一文件夹，**只留 4 个 md**
│   ├── 剧本原文.md               原文逐字
│   ├── 剧本分镜.md               ① 改编 + ② 分镜，两层合一
│   ├── 图片提示词.md             人设 + 场景 + 分镜，三合一
│   ├── 视频提示词.md             每单元「中文块 + 英文块」并列
│   ├── gen_shots.py  gen_video.py  dump_prompts.py  check_dialogue.py
│   ├── 图片/  视频/
├── _归档/                        旧文档 / 误归档废片（**移动隔离，不删除**）
├── 项目索引.md / 引用技能.md
└── .workbuddy/memory/
```

**分层判据**：「是否全剧通用」。命名/风格/角色设定进共享层，不在分集目录重复。

🔴 **剧集目录只留 4 个 md，多一个都算噪声。**

| 文件 | 内容 | 语言 |
|---|---|---|
| `剧本原文.md` | 原文逐字 | 中文 |
| `剧本分镜.md` | **① 改编 + ② 分镜两层合一**（先改编定集定人定对白，再分镜切秒级时间码） | 中文 |
| `图片提示词.md` | **人设 + 场景 + 分镜三合一**（凡生成图片的提示词都在这） | **中文（不动）** |
| `视频提示词.md` | 每单元「中文块 + 英文块」并列 | **英文块为生成正体** |

中间产物（旧提示词、dump、备份）一律移入 `_归档/<集号>_旧文档_<日期>/`，**移动而非删除**。

## 图片命名

### 关键帧

```text
<单元>_<镜号>_关键帧.png        例：U01_S02_关键帧.png
```

- 按画风分子目录放：主画风 → `图片/<主画风 ref_subdir>/`（如 `图片/ref3d/`）；
  **整活镜 → `图片/qban/`**，两套不混放，避免互相覆盖

### 角色四视图

```text
CH##_四视图_<风格标记>.png       基准件（一切变体的源图）
CH##_四视图_<装束名>.png         装束变体
CH##_四视图_Q版.png             Q版形象（叠加画风，见下）
CH##_Q版表情_<情绪>.png         Q版表情变体（从 Q版基准件派生）
```

> **风格标记取自所选风格文件**（`styles/<style_key>.md` 的 `asset_tag`）：
> `guoman-3dcg` → `3DCG`，即 `CH01_四视图_3DCG版.png`。
> 🔴 **风格标记 ≠ 版本号**：`_3DCG版` 与 `_古风CG版` 是**两种风格**，不是同一画风的两个版本。
> 版本号（`_v2` / `_v3`）是另一套东西，只用于**同一风格内的重生成**（见「版本后缀规则」）。
> 项目里并存多套画风时，**每张资产都必须带风格标记**，否则两张基准件会互相覆盖。

标准命名示例：

```text
CH01_四视图_3DCG版.png          基准·日常常服（国漫 3D CG）
CH01_四视图_寝衣版.png          寝衣·夜半初醒
CH01_四视图_红袍朝服版.png       红袍·亲王常服
CH01_四视图_衮冕帝王版.png       衮冕·帝王
CH01_四视图_现代版.png          现代·学生
CH01_四视图_Q版.png            Q版形象（叠加画风 `chibi-gag`，仅整活镜用）
```

> **`_Q版` 是风格标记，不是装束变体**（`styles/chibi-gag.md` 的 `asset_tag`）。
> 它与主画风基准件**并存**，互不替代：主画风镜头投 `_3DCG版`，整活镜投 `_Q版`（R37）。

- 尺寸：**固定 16:9 → `1680x944`**（被 16 整除；**与成片画幅无关，改画幅不用重出**）
- 版式：**横向四分格** = `半身正脸` ｜ `全身正视` ｜ `全身侧视` ｜ `全身背视`；纯色背景、无边框无分隔线
- **主角凡在剧情中出现过的装束，都要有对应变体**；变体一律从基准件图生图派生
- 生成脚本支持 `--force`；**不加则跳过已存在的，不覆盖**

### 场景参考图

```text
SC##_<场景名>.png               例：SC02_村道.png、SC03_徐家堂屋.png
```

- 尺寸：**与成片画幅一致** → 16:9 用 `1680x944`；9:16 用 `1024x1536`（⚠️ `1536x1024` 是 3:2，不是 16:9）
- 内容：空场景或极简人物，突出建筑形制、地貌、材质、光线基调
- **同一场景全剧复用一张**，不要一集一版
- 存放：`_共享资源/02_场景设定/`（🔴 不是 `04_参考图`，那个目录已废）
- 用途：图片与视频生成时的**环境依据**（锁空间与材质；与关键帧参考对齐、不锁死调度）
- **有实景照片时从照片 `image_edit` 重建**，不要凭文字想象重画

### 屏幕 / 面板图（`EP##/图片/`）

```text
PANEL_<台词编号>_<内容短名>.png     例：PANEL_S1_绑定邀请.png、PANEL_S2_支付成功.png
PANEL_BASE_<状态名>.png           空白 / 无字态，例：PANEL_BASE_空白卡槽.png
```

- 🔴 **按集存放**（`EP##/图片/`），**不进 `_共享资源/`**——共享层只有 `01_角色设定` / `02_场景设定` / `03_风格与提示词规范` 三个目录
- 编号取**对白稿里的台词编号**（`S1`/`S2`…），便于追溯「这块面板对应哪句系统台词」；空白态用 `BASE`
- **一个文案 = 一张图**（不同文案就是不同状态），不要指望一张图改字
- 内容：**纯黑底 + 面板居中**，无房间 / 桌面 / 手 / 人物 / 环境光；**文字由图像模型排版**
- 生成器：`EP##/gen_panel.py`（`--list` / `--force` / `--dry-run`）
- 🔴 **投喂时必须声明「黑底视为透明、按屏幕叠加」**，否则会被当成实心黑框画进画面

## 视频命名

```text
<单元>_<镜号范围>.mp4            例：U01_S01-S04.mp4
```

### 🔴 版本后缀规则

> **本节只管「同一风格内的重生成」，与画风无关。**
> 换画风产出的是**一整套新资产**（带新的**风格标记**，走 `styles/` 里另一个风格文件），
> **不是** `_v2`。别把两种风格写成两个版本。

**禁止覆盖或删除旧版本。** 同一单元重生成时：

| 情况 | 做法 |
|---|---|
| 首次生成 | 不带版本后缀 |
| 已存在同名 | 新版加 `_v2` / `_v3`…，旧文件不动 |
| `task_id` 对应 | `EP01U01`→`_v1`、`EP01U01b`→`_v2`、`EP01U01c`→`_v3` |

> **教训**：生成成功后应**立即复制归档**到 `EP##/视频/`，
> 否则产物只躺在 `save/`，项目目录看起来是空的，险些误判为没有产出。

## 提示词文档的文件结构（脚本解析契约）

> ⚠️ 生成脚本按此结构解析。**改动结构会导致解析失败。**
> 剧集目录下有**两份**提示词文档，分工不同：

| 文档 | 语言 | 参与脚本解析 |
|---|---|---|
| `视频提示词.md` | **中文块 + 英文块并列** | ✅ `gen_video.py` / `check_dialogue.py` |
| `图片提示词.md` | **中文** | ❌ 人读的汇总（改提示词要改生成器，见下） |

### 视频提示词.md

```text
# U01 · <单元标题>            ← 一级标题，形如 U<数字>[ab]
## 投喂信息
| 项目 | 值 |               ← 模式/总时长/画幅/分辨率/音频/节奏档位/台词/图片参考
**素材映射**
| 引用 | 文件 | 用途 |       ← 首列必须是 （@图片N），第二列文件名带扩展名
**台词与时长核算**
| # | 角色 | 台词 | 含标点字数 | 时长 |
## 提示词
### 中文                     ← ① 中文块在前（仅供人工核对）
```text
<中文正文>
```
### 英文                     ← ② 英文块在后（**实际投喂**）
```text
<英文正文>
```
```

| 项 | 约定 |
|---|---|
| **块序** | **中文在前、英文在后**（贴合阅读习惯）。取块靠**表头定位**，顺序与解析无关 |
| **表头** | 固定 `### 中文` / `### 英文`，**不加任何括注**（不写口径名、不写「生成用/对照」） |
| 正文语言 | **英文块是生成正体**；中文块只为人读。两块**同为当轮口径**，以便只差语言、逐句比对 |
| 台词 | `<d>[Chinese] …</d>` 内文字两块**逐字相同**（台词不译） |
| 引用 | `（@图片N）` 的编号与数量两块**必须一致** |
| 元数据表 | **中英共用一份**，保留中文表头（解析契约，不属于提示词） |

> 🔴 **为什么同文档并列而不是两份文件**：两份文件各自维护会立刻失去同步；
> 并列则改一处就能同时看到中英对照。代价是**取块必须靠表头**，不能取「第一个代码块」。

### 图片提示词.md（三合一，不参与解析）

一份文档收齐**所有生成图片的提示词**，按三类分部分：

```text
## 第一部分 · 人设提示词（角色四视图）    ← CH## + 装束变体，逐条附完整提示词
## 第二部分 · 场景提示词（环境参考图）    ← SC##
## 第三部分 · 分镜提示词（关键帧）        ← <单元>_<镜号>
```

> 🔴 **它是导出物，不是源。** 真源在各生成器的常量里：
> 人设 → `_共享资源/01_角色设定/gen_char*.py`；场景 → `_共享资源/02_场景设定/gen_scene.py`；
> 分镜 → `EP##/gen_shots.py`。
> **导出方式：脚本 import 生成器模块、调用其 build 函数逐字写盘**，不要手抄——
> 手抄会与代码脱节。改提示词改生成器，再重新导出。
>
> ⚠️ 分镜部分的导出命令**不要直接重定向到 `图片提示词.md`**，会覆盖掉人设与场景两部分；
> 先导到临时文件，再并入第三部分。

### 解析硬约束

| 项 | 要求 |
|---|---|
| 单元标题 | `# U01 · …`，形如 `U<数字>[ab]`，**必须是一级标题**。**整活单元标题带 `整活` 字样**（如 `# U05 · 整活·紫蛋`），解析规则不变（仍只认 `U\d+`） |
| 提示词 | 先按 `--lang` 定位 `### 中文` / `### 英文` 表头，再取**该段第一个** ` ```text ` 代码块。旧单语格式（无表头）自动兼容，取章节内第一个块 |
| 素材映射 | 单元章节内的表格，首列 `（@图片N）`（可加反引号），第二列文件名需带扩展名 |
| 文件名解析 | 先查 `EP##/图片/`，再查 `_共享资源/01_角色设定/`（四视图）与 `_共享资源/02_场景设定/`（场景图） |
| 图片上限 | **7 张**（服务端 NODE_IMAGES 节点数；项目可自定更严约定） |

### 🔴 文档自指污染

**描述文件结构时不能写出裸的 `# U01` 形式标题** —— 脚本会把它当成真单元解析出来。
说明性文字务必用**四反引号**（````）包裹，或改用 `U<序号>` 占位写法。

> **教训**：曾在 `提示词.md` 里写「`# U01 · <单元标题>` ← 一级标题」，
> 脚本解析出一个名为「U01 · \<单元标题\>」的假单元，还吃掉了真 U01 的素材映射。

## gen 脚本约定

### gen_shots.py（关键帧）

```bash
python gen_shots.py <单元> [镜号]     # 单张生成
python gen_shots.py ALL              # 批量（串行，慎用）
```

- 无参数时打印用法与可用单元列表
- 已存在的文件跳过，不覆盖
- 纯文生图（`/images/generations`）：角色一致性靠**文字锁定常量**，
  无法传四视图参考（能力缺口，见 character-consistency.md）
- **提示词必须符合逻辑与一致性**（红线 R8c）：角色常量与场景词逐字复用、带画风尾串，
  详见 character-consistency.md 「图像生成提示词」一节

### gen_video.py（视频）

```bash
python gen_video.py --list            # 列出全部单元与解析结果
python gen_video.py <单元>            # 提交 + 轮询 + 落盘（默认滑动窗口并发）
python gen_video.py ALL               # 全部（滑动窗口，最多 5 个在飞）
python gen_video.py <单元> --jobs 3   # 手动调并发（上限 5）
python gen_video.py <单元> --suffix b # 重生成（task_id 加后缀）
python gen_video.py <单元> --dry-run --suffix b  # 只上传不提交
python gen_video.py <单元> --lang zh  # 改投中文块（一般不用；默认 en）
```

- 运行时解析 `视频提示词.md`，**不硬编码提示词**
- **`--lang` 默认 `en`** → 取 `### 英文` 块；`--lang zh` 取 `### 中文` 块（仅供核对）
- 归档名带语言标记：英文版 `U04_S09-S11_en.mp4`，与中文版**并存不覆盖**
- 🔴 **换语言要连带改三处**，漏一处就出哑巴问题（见 R32 / prompt-format §6）：
  ① **字数闸门换制**（中文按字符 1900 / 英文按**词** 1100）；
  ② **跳过中文风格层替换**（中文正则命不中英文文本，硬跑只会误追加一段中文收敛项）；
  ③ **自检换词表**（中文 A / B 类词表跨语言套用会全量误报或漏报）
- 参考图自动上传：读素材映射表，按 `（@图片N）` 顺序上传，走 I2VA
- **提交前先探测服务**，不通则打印启动提示并退出
- 已落盘则 SKIP；重生成必须加 `--suffix`
- `finished` 但未落盘时，自动从 raw 里挖直链补调 `/save_video`
- 解析用 `re.finditer(r'^#\s+(U\d+[ab]?)\b.*$')`，不能用 `re.split(r'^# ')`
  （会切碎标题）
- 🔴 **并发用滑动窗口**：`ThreadPoolExecutor(max_workers=5)`，一次性把所有单元丢进去，
  **任一落盘即自动补下一个**。**不要分批**（每批等最慢的会空转）、
  **不要一次全丢**（上游上限约 5，超了返 `code 605`）。
  单元日志必须加 `[U06]` 前缀 + 加锁，否则并发输出会串。

### 🔴 gen_video.py 的必查点（都踩过）

| # | 必查 | 不查的后果 |
|---|---|---|
| 1 | **`aspect_ratio` 传完整枚举**（`16:9 (Widescreen)`） | 传裸 `16:9` → 上游 `ResolutionSelector` 校验失败 → 任务 0 秒 FAILED |
| 2 | **提交后校验响应体**（`ok` + `upstream_task_id`） | 上游报错被服务端透传、HTTP 仍 200 → 误判成已提交，白等一轮 |
| 3 | **落盘文件校验 mtime ≥ 提交时刻** | `saved` 会命中**历史日期目录里的同名旧文件** → 0 秒拿到昨天的成片，归档废片 |
| 4 | **`task_query` 返 404 立即中止** | 那是"提交根本没成功"的信号，空转轮询 30 分钟 |
| 5 | **并发限到 5 以内** | 第 6 个提交返 `code 605`，且其 msg 误导成"余额不足" |

### 多风格项目的视频提示词

两种做法，按「文档是否已含目标口径」选：

**A. 文档已按目标口径写成（当前推荐）**
`--style` 只管**参考图的选取**（`图片/<风格>/`、`CH##_四视图_<风格>*`），不做文本替换。
此时风格层替换函数退化为**兜底**：对已是目标口径的正文是**幂等**的
（正则不命中、收敛项不重复追加），不会误伤。

**B. 文档是旧口径、要切到新口径**
让 `--style` 额外做文本替换，共两件事：

1. **参考图按风格解析**：`_关键帧.png` → `图片/<风格>/`；`CH0X_四视图_古风CG_*` → `_3DCG*`
2. **提示词风格层按规则替换**：只替换**光质/渲染描述**（渲染路线、光影档、收敛项），
   **保留每单元特有的内容**（谁依哪张图、光源在哪、色调压窄成什么、这段要什么效果），那些是叙事。

替换用正则而非逐字匹配：同一风格短语在各单元会略有变体
（`光影用柔光档：柔和三点打光，轮廓光分离人物与背景，` /
`内室段用柔光档：…轮廓光把人物从暗背景里分离出来，`），
写死字符串会漏替换。**替换后要跑一遍残留自检**（搜旧风格关键词），确认干净再提交。

> 🔴 **无论哪种做法，都不要为了切风格去复制提示词文档** —— 长文档复制两份会立刻失去同步。
> 兼容旧格式：解析器对「没有 `### 中文` / `### 英文` 表头」的单语文档**自动回退**为取章节内第一个代码块，
> 所以旧文档不会因为换了结构就跑不了。
