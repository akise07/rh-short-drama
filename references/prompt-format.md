## 0. 结构总览

```text
生成一段<N>秒、<画幅>、<分辨率>、原生立体声的<风格>短片。<场景与资产锁定描述>

素材：（@图片1）为<角色>四视图；（@图片2）为<场景>参考图；…

<起>—<止>秒：<空间+人物动机+动作+情绪>。镜头<轨迹 + 幅度 + 速度>。
<起>—<止>秒：…动作链下一环，受力传递…
<起>—<止>秒：…终结动作…

剪辑与动作：<轴线 + 切点节点 + 受力传递链 + 镜头语言 + 慢动作规则>
视觉风格：<渲染质感 + 材质细节 + 光照 + 色调 + 特效运动>
声音设计：<声道布局 + 音效材质/距离/力度 + 高低潮声学> 全程无配乐
```

**语言**：全部中文。台词原文语言保留不译。

### 🔴 画幅口径（先确认再写）

**开篇声明的画幅必须与项目成片画幅一致**，且与关键帧/场景图尺寸一致。
**角色四视图是例外**：它固定 16:9，不随画幅变。

| 画幅 | 声明写法 | 关键帧/场景图 | 角色四视图 |
|---|---|---|---|
| **16:9 横屏（🔴 默认，番剧/影视向）** | `生成一段N秒、16:9、2K、原生立体声的…` | `1680x944` | **固定 `1680x944`** |
| 9:16 竖屏（**改画幅时适用**，滑刷短剧） | `生成一段N秒、9:16、2K、原生立体声的…` | `1024x1536` | **仍为 `1680x944`**（四视图与画幅无关） |

> ⚠️ **`1536x1024` 是 3:2，不是 16:9**。16:9 一律用 `1680x944`（被 16 整除）。

同时 `/gen_video` 的 `aspect_ratio` 要传**上游完整枚举**（`16:9 (Widescreen)` /
`9:16 (Portrait Widescreen)`）。**不要传裸冒号形式**，服务进程可能落后于源码、裸值会被原样透传，
导致任务 0 秒 FAILED（见 SKILL R21a）。
**三者（提示词声明、关键帧/场景图尺寸、提交参数）必须一致**，错一个就是返工。

> 本项目默认 **16:9 横屏**（用户 2026-09-20 定），改 9:16 须显式说明（见 SKILL 第 0 节与 R21）。
> 一旦改画幅，**旧画幅的关键帧与场景图全部作废重出**，且**节奏档要同步换**（见 `rhythm.md`）。
> **角色四视图不用重出**，它固定 16:9。

**十个必须做到的点**

| # | 要求 | 反例 → 正例 |
|---|---|---|
| 1 | **秒级时间段落** | `[Shot 1] 00:00-00:01.5 — 锄头铲到硬物` → `0—0.5秒：低机位大特写，锄头高速铲入干硬黄土…土屑呈扇形飞溅。` |
| 2 | **动作受力传递** | 「动作链 A→B→C」→「上一画面的结果直接启动下一画面」 |
| 3 | **精确镜头轨迹** | 「镜头缓推」→「沿手部动作方向小幅慢速下压推近」 |
| 4 | **材质具体化** | 「材质真实」→「干土哑光碎屑感，锈铁暗哑氧化层」 |
| 5 | **声音声道分层** | 「有风声」→「左右声道铺开坡地风声，中央声道锄刃单次金属脆响」 |
| 6 | **开篇声明规格** | 直接开始描述画面 → 「生成一段6秒、16:9、2K、原生立体声的…」（**画幅按项目口径**，默认 16:9，见下） |
| 7 | **必须显式引用参考图** | 通篇无 `（@图片N）` 即失败 |
| **8** | **逻辑描述优先** | 只写动作骨架 → 写清动机/情绪/空间/因果，让模型自行调度 |
| **9** | 🔴 **提示词全文不含双破折号 `——`**（文档行文不受限） | 破折号后面的字会被念进台词（见 §2b「来源一」） |
| **10** | 🔴 **全文 ≤1900 字**（含自动注入的声明） | 超限会被上游拒绝或截断（见 SKILL R10/R26） |

## 1. 秒级时间段落

### 格式

```text
<起>—<止>秒 | <焦距> | <运镜方式>：<空间 + 人物动机 + 动作 + 结果 + 情绪>。镜头<轨迹 + 幅度 + 速度>。
```

- 🔴 **段头三件套**（2026-09-21 起，用户口径）：`<时间段> | <焦距> | <运镜方式>：`，**每一段都必须有**。
  | 项 | 取法 |
  |---|---|
  | **时间段** | `起—止`，与既有口径一致（单个 `—` 是格式骨架，不受 R2a 的双破折号禁令约束） |
  | **焦距** | 按景别取：大特写 / 特写 `85mm`、近景 `50-85mm`、中景 `35-50mm`。🔴 **最远只到中景（35mm），禁用 `24mm` / `18mm` 这类超广角**（用户 2026-09-21 口径：人物离镜头过远会渲染崩掉）。**单镜内换焦段时写序列**，如 `50mm→85mm` |
  | **运镜方式** | 用固定词表，不要即兴造词：固定 / 微推 / 轻推 / 快推 / 拉 / 横移 / 跟移 / 跟拍 / 仰摇 / 俯摇 |
  - **英文块**对应写 `0—2.5s \| 85mm \| locked off, micro push-in:`、`7.2—8.4s \| 24mm \| lateral track right to left:`。
  - **作用**：让「景别感」与「镜头运动」在段头一次交代清楚，正文就可以专心写动作与表演，不必每段再解释镜头；也便于人工逐段核对镜头参数。

- 🔴 **段落 = 镜，一一对应**（用户 2026-09-21 口径：「视频提示词不要大分镜包含小分镜，每个分镜都是不同的时段」）：
  - **段数必须等于该单元在 `剧本分镜.md` 逐镜表里的镜数**，且**时段边界与镜边界逐一对齐**（相对时间）。
  - **段内不允许出现切点**。写「第 2.2 秒切镜到近景」＝把多个镜压进一个时段，模型会读成一次生成里自己切刀。
  - 一镜到底的长镜，段头要显式写「**一镜到底、段内不切**」；段内的「约第 4 秒他抬手」只是**表演节拍**，不是切点。
  - **跨镜的长台词**（R3 不得跨段拆）→ **合并镜**并标 `[豁免:长镜]`，**不要拆台词**（拆了会吞字或接缝停顿）。见 `SKILL.md`「锚点模式」第 8 条。
  - **必须脚本校验**：改完跑一次「时段数 / 时段边界 vs 镜数 / 镜边界」的比对，别靠人眼。本项目已有 `_tools/crosscheck_ep01.py` 可作模板。

- 分隔符用破折号 `—`（不是 `-` 或 `~`）
- 首段起点固定 `0`，末段终点 = 目标总时长，段落首尾相接
- 单段 < 0.5 秒模型常无法生成有效动作，与相邻段合并

### 禁止

```text
❌ [Shot 1] 00:00.000-00:01.500 — 锄头铲到硬物   ← 标题式，信息密度不足
❌ 0—0.5秒：镜头缓推                              ← 无轨迹、无主体、无结果
❌ 0-0.5秒：…                                     ← 半角连字符
❌ 有关键帧却不投喂，通篇不提，画面与关键帧脱节      ← 关键帧必须参考以保稳定（见 §3）
❌ 写「构图完全不变」「画面与关键帧一致」           ← 参考不等于复刻，会锁死调度
```

## 2. 🔴 台词格式：`<d>[Chinese] 对话内容</d>`

**所有台词一律用 `<d>[Language] 对话内容</d>` 包裹。**

| 规则 | 说明 |
|---|---|
| 每句只出现在一处 | 完整一句只写进它所属的**那一个秒级段落** |
| **禁止跨段拆分** | 分段切的是「动作节点」，不是句子。拆两段会导致接缝停顿、重复起口型、吞字 |
| **禁止段外复述** | 台词内容不得在 `<d>` 之外出现（「念到『很远很远』时」→「说到半句时」） |
| 画外音 | 直接描述声源方位：「画外传来…落下来：<d>…</d>」 |
| `声音设计` 段 | **不写台词**：只写环境声、物理音、非人声 |
| **台词占比** | 台词总时长应占成片**大部分**（目标 ≥55%），靠砍无台词剧情达成 |

> 🔴 **标签只能圈住"该念什么"，圈不住"不该念什么"。**
> 标签外的文字被念出来有两个来源，**处理手法完全不同**，见 §2b：
> **双破折号**（主因）与**动机描写贴在引导语位置**（次要）。两节都要过。

### 改编授权（2026-09-17）

**现有台词不改。** 改编只为让对话更贴合视频逻辑、更自然（调整顺序、补衔接词），
**很多时候不需要改**。

| 项 | 规则 |
|---|---|
| **现有台词** | **不改**：保留原文，措辞基本不动 |
| **主要手段** | **压缩/删除无台词的剧情段**，让对话占比自然上升 |
| **改编目的** | 让对话更符合视频逻辑、更自然；**很多时候不需要改** |
| **可选增写** | 仅对话衔接生硬时补极少量，**不作为主要手段** |
| 禁止 | 删除原文信息、改变人物设定或立场、凭空发明剧情事件 |

> **台词占比靠「砍无台词剧情」达成，不是靠加台词。** 见 `rhythm.md`。

### 正误对照

```text
✅ 0.8—9.3秒：徐多寿仰着脸，眼睛里落着门外的余光——他真心相信这件事。
   他用清脆的童音一气说完下面这句话：
   <d>[Chinese] 拜啊！李叔说，在很远很远的地方，那里的人都供奉神，神就会保佑他们的村子。</d>
   说到半句时他双手把泥像往上托了托，说完还盯着父亲等回应……

❌ 0.8—4.2秒：……说道——「拜啊！李叔说，在很远很远的地方，」   ← 引号包裹 + 切断句子
❌ 4.2—10.0秒：……把话说完——「那里的人都供奉神，……村子。」      ← 同一句拆成两段
❌ 说到「很远很远」时他双手把泥像往上托了托                     ← 段外复述台词内容
❌ 他急着解释——那村子全靠这尊泥像撑着呢                        ← 破折号，后面会被念出来
```

### 台词时长

```text
台词时长 = 含标点字数 ÷ 4.5
```

- **标点代表停顿，停顿也占时间**：不要用纯汉字字数算（会低估）
- 字数**必须用脚本数**（`len(台词)`），不凭感觉标
- 单元时长 ≥ 台词时长 + 必要表演时间
- **台词量是下限不是上限**：为达占比目标，宁多勿少

#### 🔴 逐段核对：每个秒级段落的时长 ≥ 该段台词所需时长

**单元总时长够不等于每段都够。** 这是最容易漏的一层：总账算平了，
但某一句被塞进过短的段落里，模型只能疯狂加速念白，结果是**吐字不清**。

实测踩坑（U04）：单元 14 秒 / 台词 60 字 / 13.3s，总账看着刚好，但拆开看：

| 段落 | 分配 | 台词 | 台词实需 | 结果 |
|---|---|---|---|---|
| 0到8.0s | 8.0s | 27 字 | 6.0s | ✅ 余 2.0s |
| **8.0到11.0s** | **3.0s** | **33 字** | **7.3s** | ❌ **差 4.3 秒** |

**清单化核对**（写提示词时逐条过）：

```text
段落时长 ≥ 本段台词字数 ÷ 4.5 + 起口型与收尾的余量（约 0.3-0.5s）
```

**发现缺口时不要硬压语速**，改法是：给该段加时长（同时把总时长加长），
或者按 `rhythm.md` 的规则砍/并镜次——**不要靠"让她说快一点"糊过去**。

> **顺带一条**：台词占比算的是**整集**，不是每个单元都要顶到 95%。
> 单元里塞得过满（如 14 秒装 13.3 秒台词）会挤掉表演与切镜的余地，
> 反而让成片变成"念稿"。给表演留出呼吸。

## 2b. 🔴 台词朗读边界与可懂度

`<d>` 标签之外的文字**有可能被一起念出来**。这类问题有两个来源，
**处理手法完全不同，不要混为一谈**。

### 🔴🔴 来源一：双破折号 `——`（主因，用户实测定性）

**症状**：角色念出了剧本里根本没写的话。

实测案例（U04）：朱正的台词只有 `请留步，我睡昏了头，一时有些迷糊，竟是忘了自己姓名……`，
但成片里他念出的是「请留步，**我此刻唯一的目的就是留住这个人问清处境** 睡昏了头……」

**真因**：`——` 后面的字会被一起念进台词。

```text
❌ 他急了——他此刻唯一的目的就是留住这个人问清处境。他顾不上体面，伸长了脖子喊……
        ↑ 被念出来的那半句，正好紧跟在破折号之后

✅ 他急了，顾不上体面，伸长了脖子朝廊下的方向喊……
   （要保留那句动机，就让它独立成句，或移到台词之后）
```

**机理**：`——` 是**连接/解释**符号，模型会把它理解成"同一句话的延续"，
于是把后面的说明文字当作句子的后半截继续读下去。
**句号 / 逗号是分隔符，不会被连读** —— 所以提示词里一律把破折号降级为分隔符。

> ⚠️ **本节早期版本把根因误判为"动机描写贴在引导语位置"**（认错了标本）。
> 真凶是**标点本身**。位置上贴近引导语确实增加风险，但**只要拿掉破折号，
> 同一段文字放在那里就不会被念**。改标点比改语序更根本、代价也更小。
> **教训：归因要靠对照实验，别拿"看起来可疑的邻近因素"当结论。**

> ⚠️ **时间码里的单个 `—`（如 `0—2.2秒：`）不在禁用之列**：
> 它是秒级段落的格式骨架（见 `naming.md` 的解析契约），不是标点用法。
> **只禁双破折号。**

#### 三条贯彻纪律

| # | 纪律 |
|---|---|
| 1 | **提示词里一律换成句号或逗号**。要表达"解释/递进"，就独立成句 |
| 2 | **任何被注入到提示词里的常量，自己也要遵守这条**（见下「注入物自身的污染」） |
| 3 | **清理动作放在所有注入之后**，否则注入进来的破折号会逃过清理 |

#### 🔴 注入物自身的污染（很隐蔽）

给提示词**注入固定文本**时，**注入物自己必须遵守提示词的全部规则**：

- 边界声明初版把成对破折号用作插入语，于是每提交一个单元就往提示词里塞进
  **2 个破折号**，8 个单元全被自己的声明污染。
- 更麻烦的是：**清理函数跑在注入之前**，注入进来的破折号逃过了清理。

**三重修法**：

```python
DASH = '——'   # 定义一次，全文引用

# ① 注入常量加断言：改坏时立刻炸，不用等出片
assert DASH not in READ_BOUNDARY, 'READ_BOUNDARY 不得含双破折号'
assert '<d>' not in READ_BOUNDARY, 'READ_BOUNDARY 不得含字面 <d> 标签'

# ② 清理放到所有注入之后
prompt = apply_style_layer(cfg['prompt'])
prompt = apply_read_boundary(prompt)      # 先注入
prompt, n_dash = apply_no_dash(prompt)    # 再统一清

# ③ 提交前最后一道闸门
assert DASH not in prompt, '提交的提示词仍含双破折号'
```

> **通用原则**：**注入物与主体共用同一套约束。**
> 往提示词里加任何固定前缀/后缀时，先问一句"这段文字自己合规吗"。

### 🔴 来源二：段外文字被连读（次要）

即便清掉了破折号，**标签外的文字仍有被连读的概率**，尤其当它
① 紧贴在台词**前面**、② 落在中文引语的**引导语位置**（冒号之前）、
③ 本身是**第一人称**内心活动时。

| # | 做法 |
|---|---|
| 1 | **台词前只留"怎么说"（语速/语气/音量），把"为什么说"（动机/心理）放到台词之后** |
| 2 | 不要用破折号把动机句挂在台词前面（见上，那才是主因） |

> **判据**：台词前的那一句，读起来像不像可以直接接上台词？
> 像，就有被连读的风险。引导语位置只放**说话方式**，不放**心理内容**。

### 🔴 三层机械保证（不靠作者记性）

上面两条是**写法**，但写法是概率性的：作者会忘、单元一多必然漏。
所以再加两层**确定性**的手段：

| 层 | 手段 | 性质 |
|---|---|---|
| 1 | 写法纪律（来源一 + 来源二） | 概率性 |
| 2 | 脚本**自动注入**「朗读边界」声明 + **自动降级**破折号 | 确定性（每条必有） |
| 3 | 脚本**自检**，有高危项就不出片 | 确定性（可卡流程） |

**第 2 层：自动注入 + 自动降级**。

```python
def apply_read_boundary(prompt):
    """把朗读边界声明插到第一个秒级段落之前（幂等）。"""
    if '朗读边界' in prompt:
        return prompt
    lines = prompt.split('\n')
    for i, ln in enumerate(lines):
        if re.match(r'^\s*\d+(?:\.\d+)?\s*—', ln):
            lines.insert(i, READ_BOUNDARY)
            lines.insert(i + 1, '')
            return '\n'.join(lines)
    return prompt.rstrip() + '\n\n' + READ_BOUNDARY + '\n'

def apply_no_dash(prompt):
    """把正文里的双破折号降级为句号（幂等）。返回 (文本, 替换次数)。"""
    n = prompt.count(DASH)
    if n:
        prompt = prompt.replace(DASH, '。')
    return prompt, n
```

插入位置选**第一个秒级段落之前**（不是整条末尾），因为指令在接近被约束内容时更有效。

> ⚠️ **边界声明里绝对不能写 `<d>[Chinese] … </d>` 这类字面示例！**
> 实测踩坑：第一版声明带了字面示例，① 被自检脚本当成真台词解析
> （每个单元凭空多一条）② 更糟的是**模型可能把这段示例本身也念出来**。
> 只用文字描述标签，不给可被解析的字面形式。

> 🔴 **边界声明会挤占总字数预算（R10：≤1900），必须压到 ~100 字。**
> 实测踩坑：第一版 203 字，把接近上限的单元直接顶穿：
> U01 从 1588 涨到 **1911 字，超限**；U03 只剩 40 字余量。
> 精简到 99 字后，8 个单元全部留出 90 字以上余量。
> **它是纯固定开销，是成本不是内容。**
> 同时**在出片脚本里加字数闸门**（超限跳过并报错），
> 让人一眼看到是谁把预算顶穿的：不要指望作者每次手动核对。

**第 3 层：自检脚本**。`check_dialogue.py` 对**实际提交口径**的提示词做五类检查：

| 类 | 检查项 | 失败表现 |
|---|---|---|
| **A 朗读边界** | ① 引导语含**第一人称**（我/自己）<br>② 台词**前一句**含**动机/心理词**（目的/意图/为了/因为/心里/打算/意识到…）<br>③ 引导语过长（>45 字）<br>④ 引导语里没有任何说话方式词<br>⑤ 缺少「朗读边界」声明 | 念出没写的台词 |
| **B 可懂度** | 台词附近出现**反向词**（见下清单） | 说出来的字听不清 |
| **C 段外复述** | 台词片段（≥5 字窗口）出现在标签之外 | 同一句被说两遍 |
| **D 字数** | 超 `PROMPT_LIMIT` 告警 / 超 `PROMPT_HARD` 报错 | 被上游拒绝或截断 |
| **E 破折号** | 正文出现双破折号 | 破折号后的字被念出来 |

**四个实现细节**（都踩过）：

1. **自检必须先把自动注入的声明摘掉**再解析标签，否则会把样板里的示例当台词。
2. **自检检查的是"未降级"文本**（不调 `apply_no_dash`），否则降级一跑、
   检查永远发现不了源头问题。降级只在 `gen_video.py` 的提交链路里做。
3. **反向词要做"说话语境"过滤**：`破碎` 出现在「残破甲胄」里是误报，
   只在同句含 `台词/声音/说/念/回答/开口/语/腔/喊/嘴` 时才算命中。
4. **长度检查要剔除句首时间码**（`11.0—14.0秒：` 不算引导语内容）。

**退出码 0/1**，便于卡住出片流程。

> **核心认知**：`<d>` 标签只能圈住"**该念什么**"，**圈不住"不该念什么"**。
> 提示词里写规矩是概率性的，脚本检查是确定性的。
> **边界必须由脚本守。**

### ⚠️ 别在提示词里主动要求"含糊"

实测案例（U04）台词吐字不清，除了时间预算不足，提示词本身也在助推：

```text
❌ 喊出的声音因为用力而有点破音。语气里带着求助与交代不清的窘迫
                              ↑ 明写"交代不清"，模型会照做
✅ 喊出的声音因用力而略微发紧，但每个字都要清楚送到廊下
```

**角色可以慌，但吐字不能糊。** 情绪用「音量/语速/气息」表达，
不要用「破音/含混/交代不清」这类**直接损害可懂度**的词。

**同源反向词清单**（都会导致"听不清"，写提示词时主动避开）：

| 类别 | 词 |
|---|---|
| 声带 | 破音、破声、嘶哑到听不出字 |
| 清晰度 | 含混、含糊、交代不清、口齿不清、吞字、囫囵 |
| 断续 | 破碎、断断续续、语不成句 |
| 低声 | 咕哝、嘟囔（**要写"低但字字清楚"**） |

**改法定式**：保留情绪的物理来源（气息发紧、结巴、停顿、音量低），
**追加一句"每个字都要清楚"**。二者不冲突：慌是表演，糊是事故。

> 实测：U04/U06/U07 都踩了这条（`破音` / `破碎` / `交代不清`）。
> 这三单元的症状（"听不清"）**同源**，不是三个独立问题。
> 自检脚本会把它们一并抓出来。

## 3. 参考图引用

**有资产就必须引用。** 画好的角色四视图与场景参考图必须在提示词里用 `（@图片N）` 引用。

### 🔴 两类资产缺一不可

| 类型 | 作用 | 引用要点 |
|---|---|---|
| **角色四视图** | 锁**人物形象** | 面部结构、发型发色、服装、体态 |
| **场景参考图** | 锁**环境空间与材质** | 建筑形制、地貌、材质、光照基调 |

只引角色不引场景 → 环境每镜都变；只引场景不引角色 → 人物每镜换脸。

### 🔴 关键帧必须参考，但不强制复刻（2026-09-17 二次修订）

**分镜关键帧是视频生成的必备参考。** 有对应关键帧的单元，必须把它投喂进去
（I2VA），用于**稳定画面基调、空间关系、人物状态与光线**。

参考的意义是**保稳定**，不是逐帧复刻，提示词仍可自由调度，
只是画面不能跑偏到与关键帧无关的程度。

| 要 | 不要 |
|---|---|
| 「依（@图片1）关键帧为参考，保持人物、场景与画面基调一致」 | 「构图完全不变」「画面与之一致」「逐帧复刻」 |
| 关键帧定基准，秒级段落在此基准上写动作与调度变化 | 秒级段落凭空重写一个与关键帧无关的场景 |
| 角色四视图 + 场景参考图同时投喂，锁形象与材质 | 只投关键帧、丢掉四视图（角色会漂） |
| 无关键帧时才退回「四视图 + 场景参考图」双引用 | 有关键帧却不用，等于放弃稳定性 |

**素材映射优先级**：关键帧（稳定基准）> 角色四视图 > 场景参考图。
**冲突时**：以关键帧定画面基调，四视图锁面部与服装细节——两者都投喂，让模型综合。

**格式**：`（@图片N）`，**全角括号，前后不留空格**。

```text
素材：（@图片1）为U01_S01关键帧；（@图片2）为徐三元四视图；（@图片3）为徐家堂屋场景参考图。

0—2.5秒：画面基调、空间关系与人物状态依（@图片1）为参考。徐三元肩背塌陷靠在门框上，
面部结构、白发分布与粗布衣物质感依（@图片2），夯土墙与干裂木梁依（@图片3）。
他缓慢抬起眼睑，喉结动了一下……
```

**上限**：服务端 **7 张**（`NODE_IMAGES` 7 节点，超出 400）；项目约定 **5 张**。
典型配额：关键帧 1 + 角色四视图 1-3 + 场景参考图 1-2。

## 3b. 🔴 逻辑描述优先（2026-09-17 新增）

提示词除「参考关键帧保稳定」外，核心任务是**「把这场戏的因果、动机、情绪与空间关系讲清」**——
**关键帧给画面基准，逻辑描述给调度自由**，两者叠加才是好单元。

| 维度 | 要写清 |
|---|---|
| **人物动机** | 这个人此刻要什么、在怕什么、在忍什么 |
| **情绪走向** | 每段标注情绪的**起点与终点**（压抑→松动 / 好奇→失望） |
| **空间关系** | 谁在哪、离多远、面向谁、视线落在哪、有无遮挡 |
| **事件因果** | 为什么发生、结果如何引出下一件事 |
| **心理外化** | 可拍的细节承载内心（手指蜷起、喉结动、呼吸变浅、目光下移） |
| **情绪强度** | 明确要求**表演给足**，不温吞 |

**禁止**：只写动作不写动机（表演变机械走位）｜只写结果不写过程（模型无法补全运动逻辑）。

```text
✅ 他张嘴想问，话到嘴边却停住，喉结动了一下，把话咽了回去，目光从儿子脸上移开，
   先落在泥像上，再移向地面——他不想让儿子看到自己的表情。
   → 动机、情绪转折、心理外化、视线走向齐备

❌ 徐三元靠在门框上，抬头看见泥像，开口问：<d>…</d>
   → 只有动作骨架，没有动机与情绪，生成结果会平淡
```

## 4. 三大段

### 剪辑与动作

切点逻辑（每个切点为什么切）+ 转场方式（默认硬切）+ 受力传递链
（上一段结果 = 下一段起因）+ 节奏描述。

- 单镜单元必须说明「**为何不切**」
- 禁止「接下一段」管理语、禁止复述画面细节

### 视觉风格

五维度：渲染质感（含明确排除项）、材质细节（逐主体）、光照（方向/性质/对比）、
色调（主辅色）、镜头质感（景深/颗粒）。

- 必须复引参考图（含场景参考图）
- 禁止抽象情绪词（忧郁/史诗感）不做视觉转译

### 声音设计

全片一段，4-8 句。声道布局 + 环境声 + 动作物理音 + 非人声。

#### 🔴 只有音效，没有背景音乐

**全片不允许出现任何背景音乐 / 配乐 / BGM。**

- 不写 `non_diegetic_music` 段（**该段已废止**）
- 不写乐器、旋律、和弦、节奏型
- 不写「氛围音乐」「情绪音乐」「渐强配乐」
- 段末**必须**显式写「**全程无配乐，无背景音乐**」收束

> 🔴 **生成侧永不配乐。BGM 由用户后期自行添加**（2026-09-20 定案，不属本链路职责）。
> 因此写音效时要**给后期的 BGM 留空间**：
>
> | 要 | 不要 |
> |---|---|
> | 音效**断续、点状**出现，有静默间隙 | 全程满铺、layer 堆叠 |
> | 低频克制（BGM 的律动主要在低频） | 低频轰鸣糊住整条底噪 |
> | 中高频让给台词 | 音效压住人声频段 |
>
> 满铺的音效叠上 BGM 会糊成一团，且**后期无法补救**（音效已烧进轨里）。

> **理由**：短剧靠**音效**建立真实感与压迫感。BGM 会盖掉细节、拉平情绪。
> **情绪由音效与表演承载，不由配乐兜底。**

**音效细节要求**

| 维度 | 要写 | 不要写 |
|---|---|---|
| 材质 | 「锈铁暗哑氧化层的刮擦」「干土的哑光碎裂」「粗布经纬的摩擦」 | 「有声音」 |
| 距离/空间 | 「自画面右上方远处落下来，带户外混响」「贴近的室内闷响」 | 「远处传来」 |
| 力度层次 | 「极轻」「轻触」「单次」「连续三下」 | 「有脚步声」 |
| 混响/干湿 | 「夯土墙的沉闷吸音感」「空旷场地的长混响」 | 「有回声」 |
| 声道 | 「左右声道铺开…，中央声道为…」 | 不写声道 |

**禁用抽象词**：氛围感、情绪张力、压抑的音乐、史诗感。

```text
✅ 声音设计：原生立体声。前两镜左右声道铺开干燥空旷的坡地风声，中央声道为锄刃入土的
单次金属脆响、土块崩裂的碎裂声与双手推土的干燥沙沙声，细碎石块滚落声自右上方向左下
方移动。第三镜环境声收窄，仅保留细风与远处山鸟一两声短鸣。第四镜所有地面声源骤然抽空，
被一记深闷的水下低频包裹取代。全程无脚步声、无人声、无配乐。

❌ 声音设计：配上一段低沉压抑的音乐，营造悲凉氛围。     ← 违规：有配乐 + 抽象词
❌ 声音设计：有风声、有脚步声。                          ← 违规：无细节、无声道
```

## 6. 🔴 视频提示词一律英文（2026-09-18 用户拍板）

**所有视频生成任务的提示词，正文一律英文。** 这是 R11 的正体，旧的"全中文"口径作废。

> 🔴 **只限视频提示词。图像提示词（分镜关键帧 / 角色四视图 / 场景参考图）保持中文，不要动。**

### 保留项与英文项

| 项 | 处理 | 依据 |
|---|---|---|
| 台词 | **原样保留** `<d>[Chinese] …</d>`，中文台词不译 | R2 / R11 |
| 参考图引用 | **原样保留** `（@图片N）`，全角括号、前后无空格 | R8 |
| 元数据表 | **保留中文表头**（投喂信息 / 素材映射 / 台词核算） | 脚本解析契约，不属于提示词 |
| 时间码 | 可写 `0—8.0s:`。单个 `—` 是格式骨架，R2a 只禁**双**破折号 | R2a |
| 其余正文 | 场景、秒级段落、镜头调度、剪辑与动作、视觉风格、声音设计 → **全英文** | 本文档 |

### 🔴 六条实现要点

1. **解析器不用改**。`parse_units()` 认的是代码块、`（@图片N）`、`总时长 / 画幅` 表，
   与语言无关 —— 英文版只要保留同样的元数据表即可。
2. **字数闸门要换制**。中文按**字符**（1900 / 2000），英文按**词**
   （1100 建议 / 1250 硬；换算依据 1900 汉字 ≈ 1100 英文词，约 1.7 字/词）。
   🔴 **该上限可由项目覆盖**（2026-09-21：某项目用**不固定锚点**模式，需要写逐秒空间调度与防穿帮，
   把英文上限解锁到 **1700 建议 / 1800 硬**）。**覆盖必须写进项目规范**，并**同步改
   `gen_video.py` 的 `PROMPT_LIMIT_WORDS` / `PROMPT_HARD_WORDS` 与 `check_ep01.py` 的同名常量**，
   否则脚本闸门与文档口径会打架。
   英文若沿用字符口径，会得出一个毫无约束力的大数字。
3. **边界声明要英文版**。英文提示词里夹一段中文指令会破坏语言一致性。
   英文版同样受 R2b 约束（不含 `——`、不含字面 `<d>` 标签），照样加 `assert` 自检。
4. 🔴 **风格层与语言绑定**。若英文正文**自带**某风格口径（如 ref3d），
   切语言时必须**跳过 `apply_style_layer()`**：中文正则命不中英文文本，
   硬跑只会给英文提示词误追加一段中文「收敛项」。
   代价是英文版变成**单风格**的，要切别风格得另写英文版风格层。
5. **归档名带语言标记**（如 `U04_S09-S11_en.mp4`），与中文版并存对照（R15）。
6. 🔴 **自检的词表是语言相关的**。中文的 A 类四项（第一人称 / 动机词 /
   引导语长度 / 说话方式）与 B 类反向词**全是中文词表**，套到英文上会全量误报或漏报。
   正确做法：英文下**换英文反向词表**，A 类四项**显式跳过并在输出标注「未覆盖」**，
   **不要假装通过** —— 假绿灯比没有检查更危险。
   C（段外复述）/ D（字数）/ E（破折号）与语言无关，照常跑。

> 所以英文版的台词边界目前**只有两层保证**（写法纪律 + 注入的英文声明），
> 比中文版少一层机械自检。要补齐得另做英文词表。

### 落地实现（`gen_video.py --lang`）

源文档是**一份双语文件**，每个单元并列两个块（**中文在前、英文在后**）：

| 值 | 取哪个块 | 行为 |
|---|---|---|
| `en`（默认） | `### 英文` | **实际投喂**：注入英文边界声明、按**词**计字数（1100 / 1250）、归档加 `_en` |
| `zh` | `### 中文` | 仅供人工核对 |

- **块序中文在前**（贴合阅读习惯）；**表头固定 `### 中文` / `### 英文`，不加括注**
  （不写口径名、不写「生成用 / 对照」这类后缀）。
- 两块**同为当轮口径**，这样才能**只差语言**地逐句比对。
- 取块**靠表头定位**，不能取「章节内第一个代码块」；旧单语格式自动回退兼容。
- 归档名带语言标记（`U04_S09-S11_en.mp4`），与中文版并存（R15）。
