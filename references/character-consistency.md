# 角色与场景一致性（RH 短剧通用）

> 生成角色四视图 / 场景参考图 / 关键帧 / 带角色视频前参照。

---

## 🔴 两类资产缺一不可（2026-09-17）

图片与视频生成**必须同时参考人物与场景**。只锁一头，另一头就会漂。

| 类型 | 文件 | 作用 | 不放会怎样 |
|---|---|---|---|
| **角色四视图** | `_共享资源/01_角色设定/CH##_四视图_<风格标记>.png` | 锁**人物形象** | 人物每镜换脸 |
| **场景参考图** | `_共享资源/02_场景设定/SC##_<场景名>.png` | 锁**环境空间与材质** | 环境每镜都变 |

> 生成关键帧时也要两类都参考；视频提示词里也要两类都引用（见 `prompt-format.md` §3）。

## 角色四视图规格（🔴 统一版式，**与画幅无关**）

**2026-09-20 用户定**：不管成片是 16:9 还是 9:16，**四视图一律 16:9、一律同一套版式**。
它只锁"这个人长什么样"，不承担构图参考的职责，**所以不随画幅变**。

| 项 | 要求 |
|---|---|
| 尺寸 | **固定 16:9**：`1680x944`（被 16 整除；与关键帧的 16:9 请求口径统一） |
| 版式 | **横向四分格**，从左到右：`半身正脸` ｜ `全身正视` ｜ `全身侧视` ｜ `全身背视` |
| 左格（约占 1/3 宽） | **半身正脸照**：正面朝镜头，含头肩与上半身，脸占该格主要比例 |
| 右三格（均分剩余 2/3） | **全身正视图 → 全身侧视图 → 全身背视图**，人物大小一致、脚底对齐 |
| 背景 | 统一纯色（均匀低饱和暖灰），无环境、无道具、**无文字、无边框、无分隔线** |
| **不随画幅变** | 与成片画幅解耦。改画幅**不用**重出四视图 |

> **侧面朝向**：`侧视图` 指 **90° 正侧面**（不是四分之三侧脸）。
> 朝哪一侧不必纠结，但**全片所有角色、所有装束变体必须统一朝同一边**，
> 否则同一张图里三个格子的人会"转来转去"，拼在一起很乱。建议固定为**人物朝画面左**。

> ⚠️ **`1536x1024` 不是 16:9**（那是 3:2）。既有文档里把 `1536x1024` 当"横屏 16:9"是**口径错误**，
> 本规格明确用 `1680x944`。**被 16 整除**这条硬约束仍然成立。

> 🔴 **比旧版式好的地方**：左格从"超大面部特写"改成"半身正脸照"后，
> 上半身服装也进入左格，**装束变体时能直接验证上装有没有改**。
> 但**下装与靴子只在右侧三视图可见**，所以变体校验要**同时看左格和右侧三格**，别只看左格。

## 🔴 Q 版形象（启用 Q版整活时，可选资产）

**仅当开工第 4 问启用了 Q 版整活**（R37）才需要。规则见 `styles/chibi-gag.md`。

| 项 | 要求 |
|---|---|
| 出给谁 | **只给会在整活镜里出场的角色出**，不是全员标配 |
| 版式 | **沿用全局统一版式**（横向四分格 = 半身正脸 + 正/侧/背全身，`1680x944`），只是人物 Q 化 |
| 命名 | `CH##_四视图_Q版.png`（资产标记 `Q版`）；关键帧目录 `图片/qban/` |
| **派生方向** | 🔴 **从主画风基准件「参照」派生**：`/images/edits` 投主画风基准件，提示词要求保留**发色 / 瞳色 / 服饰配色 / 标志性配饰**，只把比例改成头身比约 1:2 |
| **可辨识性** | **验收点**：出完与主画风基准件并排看，**要能认出是同一个角色**。认不出就是失败 |
| 表情变体 | `CH##_Q版表情_<情绪>.png`，**从 Q版基准件派生**，不要跨基准（也别去改变体） |
| **投喂纪律** | 整活镜**只投 Q 版图**；主画风镜头**不投 Q 版图**（R37 / R27a） |

> ⚠️ **Q 版是"降级"不是"重设计"**：衣服款式可以简化，但**配色和标志性配饰不能换**。
> 换了配色，观众就不知道这是谁，整活镜就从"旁白"变成了"插播另一个片子"。

## 🔴 主角多形象：必须逐套出图

**主角在一部剧里往往不止一套装束**（寝衣 / 常服 / 朝服 / 帝王 / 现代 …）。
只有一张便服四视图，到了朝堂戏、闪回戏就只能现场编，人物立刻漂。

**做法**：先在剧本里**取证**，逐条列出哪些剧情需要哪套装束，标上行号依据。
没有剧情依据的形象不要凭想象加。

```text
例（某穿越剧）：
  基准·日常常服    ← 基准件
  寝衣·夜半初醒    ← 原文「华服挂在衣架上」反证本人未着华服
  红袍·亲王常服    ← 原文「换上红袍，一骑绝尘」
  衮冕·帝王        ← 原文「他很快就要当皇帝了」
  现代·学生        ← 原文「历史系研究生，修复明代雕像」
  （戎装/丧服——原文无依据，不建）
```

**派生纪律**：

1. **基准件走文生图**（`/images/generations`），做完即冻结，是整个角色的锚点
2. **所有变体走图生图**（`/images/edits`），源图**永远是基准件**
3. 🔴 **不要拿变体去改变体**，每转一手累积漂移
4. 变体提示词里**必须有「面部绝对锁定」段**，逐项列出不许动的部位：

```text
面部绝对锁定，不可改动：同一张 <年龄><性别>的脸——同样的脸型与下颌轮廓、
同样的眉形、同样的眼型与<瞳色>虹膜（不能变<错色>、不能变<错色>）、
同样的唇形、同样的鼻梁。不得改变五官形状与脸部比例。
```

5. 变体生成完**逐张目视比对基准件**，确认是同一人

## 🔴 常量以"已认可的成图"为准

**外貌常量的作用是描述"已经定下来的那张脸"，不是描述你脑中的想象。**

出图后**逐项比对成图与常量**，不一致时**回写常量去适配成图**（只要成图本身没有硬缺陷）。

> **教训**：曾把发型写成 `low topknot resting at the back of the head`（脑后低髻），
> 成图却是**头顶束发**。而头顶束发恰是那个朝代的正确形制，**是常量写错了，不是模型错了**。
> 若不回写，后续每张关键帧都会按错误的常量漂走。

**判断标准**：成图与常量不一致时，先问「哪个才符合设定与史实/世界观」。
- 成图对 → **改常量**
- 成图错（瞳色、发色、形制与设定相悖）→ **改提示词重出**

## 🔴 生成后的处置（不自我验证）

**默认不做目视验证。** 用户明确要求过「以后都不再验证」，**画面好坏由用户裁决**。
不要用 Read 工具逐张打开生成图去"检查质量"，不要自己评、自己决定重画。

| 情形 | 处置 |
|---|---|
| 脚本报 `SUCCESS` | **直接交付**，不评价观感 |
| 脚本报 `FAILED` / HTTP 400 / 传输中断 | 才处理。诊断看**提示词文本**，不看生成图 |
| 客观硬缺陷（尺寸错、文件缺失、与设定常量明确相悖） | 定点改一次即交付（R22） |

**审核类拒绝**优先往「减少负面词密度 / 去肢体强制与未成年组合 / 拆句」方向改。
**不做多轮试错，不凭个人审美反复重画**，主观好恶一律交用户裁决。

> ⚠️ **本节早期版本写着「生成完必须看一眼」，已被用户明确否决。**
> 批量出图的容错完全交给脚本的 `SUCCESS`/`FAILED` 输出，靠日志判断哪张要重试。

**仍然要做的机械核对（不涉及审美，脚本可查）**：

| 检查项 | 判据 |
|---|---|
| 尺寸 | **角色四视图固定 `1680x944`（16:9）**；关键帧/场景图与**成片画幅**一致 |
| 文件真实性 | 是本次生成的（**校验 mtime**，别把旧文件当成果） |
| 版式完整性 | 四视图四格齐全（半身正脸 + 正/侧/背全身）、版式为横向四分格 |

> **踩坑：左格服装漏改。** 出朝服变体时，右侧三视图是朝服、左格却还是常服。
> 修正：提示词里**单列一句**「左格半身照也必须穿上新装束，整张四视图必须是统一的同一套装束」。
> 左格改成半身正脸后这个问题更容易被发现（上装可见），但**下装与靴只有右侧三视图能验**，
> 校验要看两处。（这是**写法**上的预防，不是让你出图后再去检查。）

> **踩坑："常识性默认"必须显式写死。** 只写 `clear bright irises` 不写颜色，
> 模型不会替你假设"中国人 = 黑褐眼"，会自由发挥成灰蓝色。
> **肤色 / 发色 / 瞳色 / 服制这类你以为模型知道的，全都要写死，并在负面里再钉一次。**

## 🔴 角色登记纪律：`chars` / `off_screen`

关键帧脚本给每镜登记出场角色，决定**投喂哪些四视图**。这里有两个坑。

### 坑一：描述了却没登记

**文字里出现谁，就必须明确表态**：要么进 `chars`（画面内、投喂四视图），
要么进 `off_screen`（画面外、明确禁止画入）。**不许含糊略过。**

> **实测**：某镜 `shot` 写了「画面深处琴案前坐着赵筱月」，
> 但 `chars` 只登记了另两人，CH02 的四视图**没被投喂**，
> 模型只能按文字自由发挥，画出来的人不是赵筱月。

**反例与正例**：

```python
# ❌ 描述了但没登记
('U01', 'S03'): {
    'chars': ['CH01', 'CH03'],
    'shot': '...画面深处琴案前坐着赵筱月...',   # 提到却未投喂
}

# ✅ 明确表态
('U01', 'S03'): {
    'chars': ['CH01', 'CH03'],
    'off_screen': ['CH02'],      # 在画面外，显式排除
    'shot': '...本镜只有朱正与巧儿两人入画。',
}
```

### 坑二：模型自行补人

`off_screen` 是**双保险**：即使文字里没提到某人，只要场景暗示他在场
（屋内本该摆着她在弹的琴案），也显式排除一句，防止模型自行补一个人进画面。

提示词里会生成排除句：

```text
🔴 本镜画面之外、绝对不得出现在画面中的角色：<角色名>。
（此刻在场外，画面里不能有任何属于该角色的身影、衣角或面部）
```

### 自检要求

`gen_shots.py --list` 会自动跑 `audit_char_refs()`，列出所有"描述了却没交代"的角色。

> 🔴 **自检只认 `off_screen` 的显式声明，不靠文字上下文猜。**
> 曾试过用"画面之外 / 看不到"这类词去猜，报出 5 条**全是假阳性**
> （都是"故意不投喂"的合理情形）。噪音一多就会被习惯性忽略，自检也就废了。
> **宁可要求作者显式表态，也不要让自检去猜。**

| 编号 | 场景 | 用途 |
|---|---|---|
| SC01 | 青山脚下坡地 | 开场、田间 |

光照写基调（唯一暖源在哪、冷暖交界在哪），色调压窄区间。

## 🔴 图像生成提示词：必须符合逻辑与一致性（2026-09-17）

关键帧/四视图/场景图的生成提示词，**不能只堆视觉形容词**。每一句都必须**过两道关**：

| 关 | 问什么 | 不过关的例子 |
|---|---|---|
| **① 逻辑** | 这在物理上、时间上、世界观上成立吗？ | 「他站在水中，脚下扬起干燥尘土」 |
| **② 一致性** | 和已定的角色、场景、画风、前一镜对得上吗？ | 上一镜粗布短打，这一镜长袍 |

### 逻辑关：五个必查项

| 项 | 要求 | 反例 |
|---|---|---|
| **物理** | 材质/受力/重力/液体/光源方向自洽 | 湿衣不起皱、无水之地写涟漪 |
| **空间** | 人在哪、面向谁、被什么遮挡、透视合理 | 人物悬空、地面与脚不接触 |
| **时间** | 与前后镜的时间/天气/时辰/光线一致 | 前一镜黄昏，这一镜正午强光 |
| **道具** | 手持物的数量、位置、状态连贯 | 前镜空手，后镜凭空持物 |
| **世界观** | 无时代错误元素（现代物件/服饰/文字） | 古装场景出现塑料/电线/简体招牌 |

### 一致性关：三层锚定

| 层 | 锚定对象 | 写法 |
|---|---|---|
| **角色** | 外貌锁定常量 + 负面约束 | 每个含该角色的画面**逐字复用**同一段常量，不即兴改写 |
| **场景** | 场景参考图的建筑形制/材质/光照基调 | 同一场景全剧复用同一套描述词，不换说法 |
| **画风** | 统一 CG 渲染口径 | 每条提示词都带画风尾串（见下文「画风基准」） |

### 🔴 硬约束

1. **同一角色 → 同一段外貌常量**，逐字复用。**禁止即兴改写措辞** 。
   「black hair」换写成「dark hair」都会造成漂移。
2. **同一场景 → 同一套环境描述词**，全剧复用，不换同义词。
3. **每条提示词必须带画风尾串**（见「画风基准」），风格不能只写一次。
4. **必须写负面约束**，且把关键特征在负面里**再钉一次**。
5. **生成过的描述词不要回改**：改角色常量 = 全片重画，代价极高。
   仅在确认漂移时才动，且要重跑所有含该角色的画面。

### 提示词自检（出图前过一遍）

- [ ] 这一段场景在物理上成立吗？（光照/材质/受力/重力）
- [ ] 人物与地面、道具、其他角色的空间关系写清了吗？
- [ ] 与前一镜的时间、天气、光线、道具有冲突吗？
- [ ] 该角色用的是**原样复用**的外貌常量吗？
- [ ] 该场景用的是**全剧同一套**环境描述词吗？
- [ ] 画风尾串带上了吗？
- [ ] 负面约束写了吗？关键特征在负面里重复钉了吗？
- [ ] 有时代错误元素吗？（现代物件/服饰/文字）

> **一句话**：图像提示词是**在既定设定上做加法**，不是每次重新设计。
> 逻辑成立 + 与既有设定对齐，才叫合格的一张图。

## 核心铁律

1. **维护「外貌锁定 prompt 常量」**，附加到所有含该角色的画面
2. **必须显式写负面约束**，只写正面描述会发生漂移
3. 四视图 = `半身正脸` + `全身正视/侧视/背视`，横向四分格，纯色背景，**固定 `1680x944`（16:9，与成片画幅无关）**
4. 关键特征（白发/疤痕/年龄）要写 `PROMINENT` 并在负面里**重复钉一次**
5. **四视图不随画幅变**，改画幅不用重出四视图；但**关键帧与场景图要跟着画幅走**

## 外貌锁定模板

```text
# 正面（英文，交给图像模型）
<age>-year-old Chinese <gender>, <脸型/五官>, <发型发色，关键特征写 PROMINENT>,
<体型>, wearing <服装>, <配饰>. Consistent art style: 3D CG Chinese animation
film quality.
```

```text
# 负面（中文，防跑偏）
必须显得<X>，不能是<相反特征>。头发必须<关键特征>。
不能出现<时代错误元素>。不要写实真人质感，不要胶片颗粒。
```

### 示例（6 岁孩童）

```text
# 正面
6-year-old Chinese boy, thin and undernourished, slight sunken cheeks but bright
expressive eyes. Short messy black hair with a few premature white strands mixed in
at the temples. Wearing a patched, faded cloth shirt in dull grey-beige, tattered at
the sleeves. Small, dirty hands. Height about 110cm.

# 负面
必须显得消瘦、面黄肌瘦，不能是圆润健康的儿童。头发必须在鬓角处掺入少量白发。
不能出现现代服装、现代玩具。不要写实真人质感，不要胶片颗粒。
```

### 示例（35 岁但显老）

```text
# 正面
Chinese man in his mid-30s appearing prematurely aged, gaunt face, hollow tired eyes,
sallow skin. Messy shoulder-length black hair with heavy white streaks. Thin beard
stubble. Wearing a worn dark brown coarse cloth tunic, patched at the elbows.

# 负面
不能显得健康饱满，必须面黄肌瘦、暮气沉沉。头发必须掺大量白发。
不要长袍/汉服/盔甲，是粗布短打。不要写实真人质感。
```

> **踩坑记录**：曾把「35 岁」画成老头 → 补 `age 35` + NEGATIVE 加 `NOT an old man`；
> 「白发」特征不突出 → 写 `PROMINENT` 并在 NEGATIVE 重复；
> 「病态孩童」被网关拒 → 见下方审核规避。

## 群演约束

群演需要**统一口径**，且与主角形成对照：

```text
# 统一锁定（死村群演示例）
Pale gaunt Chinese villagers with completely bloodless faces, hollow empty eyes
staring blankly forward, black hair mixed with grey-white strands. Wearing patched
dull earth-toned coarse cloth. They look like wooden puppets rather than living people.

# 负面
绝对不能出现健康红润的面色。不能有笑容、光彩、生动表情（除主角外）。
不能出现老人（世界观设定关键）。
```

> **关键约束**：除主角外所有群演表情必须空洞木讷，这是「村子重新有了活气」
> 反差成立的基准。

## 🔴 图像网关审核规避

gpt-image-2 网关对**儿童 + 病理**组合审核极严。审核看的是**词组合**：

| 高风险组合 | 规避 |
|---|---|
| 儿童主体 + 任何病理化形容词（bony/gaunt/malnourished） | 病态描写移到成人主体；儿童只写中性词（thin / slight sunken cheeks） |
| 儿童 + `bare feet` | 去掉，改 `worn cloth shoes` |
| 写实摄影质感 + 人物 | 改为风格化 CG 表述 |
| 少女/儿童主体 + 一长串身体否定词（不能是成年人/妇/老/幼童、不能谄笑、不能色情化…） | **负面段收短**，硬约束只留 3–4 项；贬义强度从 `disdain / contempt` 降为 `pout`，**负面情绪改用动作与姿态承载**（下巴抬起、视线挪开） |

**审核是按整段提示词判的，不是按单句判的。** 拆句逐条送审全部通过、合起来仍被拒，
是常见现象，排查时不要只盯着一句话改，**优先降低负面段的密度与用词强度**。

> **实测案例**：某侍女角色提示词 2784 字，完整必拒（400 `upstream_text_reply`）；
> 删掉负面段即通过，但负面段拆成 7 句逐条送审**全部通过**。解法是把负面从 7 句压到 4 句、
> 贬义词降级，一次通过。**这说明"哪一句有问题"是个伪命题，要压的是整体密度。**

审核拒绝时**改写措辞而不是硬重试**，同样的组合重试也是拒。

## 生成工具环境

### gpt-image-2

- 必须走本地代理 `http://127.0.0.1:7897`
  （系统代理 6224 会 502/超时；直连会 WinError 10060）
- 可用模型：`gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`
- 尺寸必须**被 16 整除**。🔴 **两类资产尺寸规则不同**：
  - **角色四视图：固定 16:9 → `1680x944`**（**与成片画幅无关**，改画幅不用重出）
  - **关键帧 / 场景图：与成片画幅一致** → 16:9 用 `1680x944`；9:16 用 `1024x1536`
  - ⚠️ **`1536x1024` 是 3:2，不是 16:9**。旧文档把它当"横屏 16:9"是**口径错误**，已纠正
  - （`1024x1024` 方可作头像/图标，不用于本链路）
- 🔴 **实测（2026-09-21）：网关忽略 `size` 参数，按固定分辨率出图。**
  请求 `1680x944` / `1712x960` / `1024x576`，**返回全部是 `1672x941`**（比例恒 1.7768），
  宽高**不被 16 整除**、高度是**奇数**。所以：
  ① 尺寸约束是**请求侧**的，照规范传即可，返回尺寸不达标**不是传错**；
  ② 16:9 项目不受影响（与真 16:9 差 0.06%）；
  ③ ⚠️ **不要拿这些图直接当视频帧**（941 是奇数，ffmpeg `yuv420p` 会失败），
     本链路里它们只作 I2VA 参考图，安全；
  ④ 🔴 **该网关出不了竖版**：改 9:16 前先验证 `gpt-image-2.5-flare` / `gpt-image-2.5-sunburst`
     是否遵守 `size`，或改用「16:9 出图 + 裁切」，**别先按 9:16 排节奏档**；
  ⑤ **不做后处理补偿**（不缩放 / 不裁切 / 不补边），机械核对只记实测尺寸
- 凭证在 **Windows 用户级**环境变量 `GPT_IMAGE_API_KEY` / `GPT_IMAGE_BASE_URL`
  （bash 读不到，用 PowerShell `[Environment]::GetEnvironmentVariable('X','User')`）
- **批量生成必超时**：单张约 50-70 秒，一次跑多张会被 SIGTERM 杀掉。
  必须 `run_in_background` 单张逐个跑，可并行开多个后台任务（最多 10）

### 两条路各自的踩坑

**文生图（`/images/generations`）**

- 带 skip-existing 逻辑时，**重生成前先删旧文件或加 `--force`**，否则会静默 SKIP
- 凭证读取：PowerShell 落盘成临时文件 → python 正则解析；
  **不能在 bash 里调 powershell.exe**（会被安全策略拒绝）
- ⚠️ `urllib` 的 `build_opener(...).open()` **不接受 `context=` 参数**（那是 `urlopen` 的）。
  要用代理**且**要 SSL 时，把 handler 挂进 opener：

```python
opener = urllib.request.build_opener(
    urllib.request.ProxyHandler({'http': PROXY, 'https': PROXY}),
    urllib.request.HTTPSHandler(context=ssl.create_default_context()),
)
with opener.open(req, timeout=300) as r: ...
```

**图生图（`/images/edits`）**

- 变体的**左格半身照容易漏改服装** → 提示词单列一句强制统一（下装与靴看右侧三视图）

## 画风基准：以 `styles/` 预设为准（本节为简版摘要）

🔴 **画风的完整口径在风格预设文件里，本节只是摘要。**
项目选定哪套风格，就读那个文件：`styles/<style_key>.md`（见 SKILL「风格预设」节）。
**两者不一致时，以风格文件为准**（并回头修正本节）。

| 项 | 口径 |
|---|---|
| 默认预设 | `styles/guoman-3dcg.md`（国漫 3D CG） |
| 怎么选 | **开工时列出 `styles/*.md` 让用户挑**，不要替用户默认 |
| 风格文件给什么 | 风格特征八维 + **中英双锁定串** + NEG + 资产命名标记，写提示词时**整串照抄** |
| 换风格 | 资产全部重出（R21）；风格层与投喂参考图必须同风格（R27a） |

以下是「国漫 3D CG」的速记要点（详版见 `styles/guoman-3dcg.md`）：

- 皮肤光滑细腻、次表面散射柔和，**无毛孔细节**
- 五官美术化精致，眼睛略大于真人、清晰高光
- 头发一束束三维建模（块面化），不是写实细发丝
- 柔和三点打光 + 轮廓光，角色与背景分离
- 干净渲染、渐变平滑，**无噪点无胶片颗粒**
- 色调 **暖金 × 青灰**双色调，浅景深

提示词必须写：`photoreal-leaning CG rendering`、`NOT stylized, NOT cartoon,
NOT anime, NO enlarged eyes`。

> ⚠️ **「眼睛略大于真人」与 `NO enlarged eyes` 不冲突**：后者禁的是**动漫式夸张大眼**，
> 不是"稍微放大"。正面写"略大于真人 + 清晰虹膜高光"，负面写"不要动漫式夸张大眼"，**别只写一半**。

> **踩坑**：曾误判「要更强 CG 感」而改卡通化（大眼/赛璐璐/平涂），用户反馈
> **不如原来的写实版**，不要走极端，风格化 3D CG 渲染即可。

> ⚠️ **本风格只是预设之一**。开工前先问用户画风（见 SKILL 第 0 节与「风格预设」节）。
> 若用户要 2D 漫剧 / 赛璐璐 / 写实影视质感，**不要在这里改写本节**，
> 而是按 `styles/` 的模板新建一个风格文件，资产全部重出。
